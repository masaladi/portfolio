Real-time document collaboration platform

0 → 100K+ DAU · Built solo, end to end

A SaaS product where multiple people edit the same document at once — where every millisecond of sync lag and every lost keystroke is a support ticket.

Problem

Real-time collaborative editing that had to stay correct under concurrent edits, and scale from a pilot to six figures of daily users without a rewrite.

What I built

Owned the whole backend: service architecture, the sync/collaboration layer, data model and delivery. Spring Boot, Redis for cache and coordination, MySQL with read replicas, async pipelines for the heavy work.

Result

Grew past 100K daily active users with the original architecture intact — cache warming, replica reads and background jobs absorbed the growth instead of a re-platform.

E-commerce order & inventory backend

Multi-tenant · REST APIs

A commerce backend handling orders and stock across multiple sales channels and tenants, where correctness of the numbers is the whole product.

Problem

Stock held in several places at once, orders arriving from more than one channel, and no single source of truth — the classic recipe for oversells and manual firefighting.

What I built

Order and inventory services with clean REST APIs, idempotent webhook handling, locking around stock mutations, and rate limiting on the public surface. Designed the schema and the integration contracts.

Result

One authoritative stock number, automated order flow, and an API surface the client's own team could build on without touching internals.
